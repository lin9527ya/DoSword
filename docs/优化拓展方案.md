# DoSword 优化与拓展方案

> 本文档基于对 `src-tauri/src/`（`lib.rs`、`commands.rs`、`session.rs`、`storage.rs`、`protocol/php.rs` 全 2752 行）与 `crates/dosword-sdk/` 的完整代码审阅，给出分阶段的性能优化、安全加固与功能拓展方案。所有结论均标注了具体文件与行号，可追溯、可执行。

---

## 一、现状分析

### 1.1 架构总览

| 层 | 文件 | 职责 |
|---|---|---|
| 入口 | `src-tauri/src/main.rs` / `lib.rs` | Tauri 启动、`AppState` 装配、命令注册 |
| 命令层 | `src-tauri/src/commands.rs` | 全部 Tauri command，统一走 `blocking()` 调度 |
| 会话层 | `src-tauri/src/session.rs` | 内存会话注册表（TTL 4h） |
| 协议层 | `src-tauri/src/protocol/php.rs` | PHP 蚁剑式协议（nonce 帧 / 编码器 / 文件 / 终端 / DB） |
| 存储层 | `src-tauri/src/storage.rs` | SQLite（WAL + 迁移 v1–v4） |
| 终端 | `src-tauri/src/pty.rs` | PTY 注册表（`Arc<Mutex<TcpStream>>`） |
| 授权 | `src-tauri/src/auth.rs` | 范围 / 过期校验 |
| SDK | `crates/dosword-sdk/` | 编码器、stub 生成、功能插件、bypass |

### 1.2 核心设计优点（已确认）

- `commands.rs` 采用 **`blocking()` = `spawn_blocking`**，同步命令体跑在阻塞线程池，主线程 / async runtime 不冻结。
- **锁内取数、锁外网络** 模式正确：`with_session` 短锁克隆 `Arc<dyn SessionState>` 后在锁外执行网络调用，单个慢请求不阻塞其他会话。
- 协议层 **只生成白名单模板**，不提供任意 PHP 透传（除 `run_code` 插件通道外）。
- 编码器、stub、功能插件、bypass 已插件化，扩展性好。

### 1.3 已确认的性能瓶颈（按影响排序）

| # | 瓶颈 | 位置 | 影响 |
|---|---|---|---|
| 1 | 目录列表远端 O(N) 次 stat：`list_dir` 模板对每个条目调 `is_dir/filesize/filemtime` | `php.rs:928-933` | 大目录（数千文件）极慢 |
| 2 | 无目录列表缓存：每次浏览都全新网络往返 | 全 `list_dir` 链路 | 反复浏览重复开销 |
| 3 | `probe()`/`connect()` 重复建客户端：`build_client` 丢弃式创建，连接池不复用 | `php.rs:784,866` | 每次探测/连接重建连接池 |
| 4 | 上传无分块：`upload_file` 整文件 base64 一次性传输 | `commands.rs:1394-1417` | 大文件内存峰值高、无续传 |
| 5 | 分块大小硬编码 4MB | `commands.rs:1455` | 无法按网络/目标调优 |
| 6 | 每命令重复 DB 查询：`session_ctx` 每次查 shell + settings 两条 SQL | `commands.rs:1242-1261` | 高频操作锁竞争 + IO |
| 7 | 请求日志全局 Mutex 竞争：每条帧 `record_request` 都抢 `REQUEST_LOG` 锁 | `php.rs:173,209` | 并发多会话时热点 |
| 8 | `SessionManager::get()` 不清理过期：只读路径残留过期会话 | `session.rs:55` | 内存膨胀（轻微） |

### 1.4 安全现状（已确认较完善）

- ✅ 授权门：`require_authorized_for`（全局开关 + 授权范围 + 勾选确认）→ `auth::scope_allows`（exact/suffix/CIDR/*）。
- ✅ 过期校验：`auth::require_session_alive`。
- ✅ DB 驱动白名单 `DB_DRIVERS`（`php.rs:133`）。
- ✅ 请求日志密码脱敏 `record_request`（`php.rs:178-214`）。
- ⚠️ **`run_code` 通道无命令白名单 / 长度 / 超时限制**（`php.rs:671`）——插件代码可任意 PHP 透传，是最大敞口。

## 二、优化方案

### 阶段一：性能优化（高 ROI，低风险）

#### P1. 目录列表：合并 stat + 补 perms ✅ 已完成

**改动：`php.rs:928-933` 的 `list_dir` 模板**

将每项的三次系统调用（`is_dir` + `filesize` + `filemtime`）合并为 `is_dir` + 单次 `stat()`，并补齐 `perms` 字段（与 SDK 原生/会话编码器保持一致）：

```php
$s=@stat($full);$is_dir=is_dir($full);
$out[]=array(
  'name'=>$f,'path'=>$full,'is_dir'=>$is_dir,
  'size'=>($is_dir||$s===false)?0:$s['size'],
  'mtime'=>($s===false)?0:$s['mtime'],
  'perms'=>($s===false)?'':substr(sprintf('%o',$s['mode']&0777),-3)
);
```

- 用单次 `stat()` 替代 `filesize()` + `filemtime()`，减少远端系统调用。
- **补上 `perms` 字段**：原 legacy 模板不产出 `perms`，而 `FileEntry` 有该字段（`php.rs:334`），前端权限列实际一直为空——这是既有 bug，已顺带修复。

#### P2. 目录列表缓存（LRU + TTL）

**改动：`commands.rs` 新增缓存层 + `AppState` 增加字段**

在 `AppState`（`lib.rs:16-22`）新增：

```rust
pub dir_cache: Mutex<lru::LruCache<String, (u64, DirListing)>>,  // key = session_id:path
```

- `list_dir` 命中缓存（TTL 内，如 5s）直接返回，跳过网络。
- 写操作（`write_file`/`delete_path`/`rename_path`/`create_dir`/`touch_path`/`upload_file`）按会话失效该会话所有缓存条目，保证一致性。
- 依赖 `lru` crate（轻量），或手写 `HashMap + VecDeque` 避免新依赖。

#### P3. 客户端复用 + 连接池

**改动：`php.rs:747-855` `probe()` 与 `connect()`**

- `probe()` 内丢弃式 `build_client`（`php.rs:784`）改为复用会话持有的 client；`connect()` 复用同一 client。
- 每 Shell 一个 `reqwest::blocking::Client` 即可维持 Keep-Alive 连接池，避免重复建连。

#### P4. 上传分块 + 断点续传

**改动：`commands.rs:1394-1417` `upload_file`**

当前整文件 base64 → `write_file`。改为复用 `write_chunk` 分块：

```rust
const CHUNK: u64 = 4 * 1024 * 1024;
let mut offset = 0u64;
while offset < bytes.len() as u64 {
    let end = (offset + CHUNK).min(bytes.len() as u64);
    ctx.protocol.write_chunk(session, &remote_path, &bytes[offset as usize..end as usize], offset, &ctx.settings)?;
    offset = end;
}
```

- 内存峰值从「整文件×2（原文+base64）」降到 4MB。
- 前端可暴露 `offset` 参数，失败后从 `offset` 续传。

#### P5. 分块大小可配置

**改动：`commands.rs:1455`**

将 `const CHUNK: u64 = 4 * 1024 * 1024` 改为从 `AppSettings` 读取（新增 `chunk_size_mb` 字段，默认 4），下载/上传共用。慢网络可调小、快网络调大。

#### P6. 命令上下文缓存（减少重复 DB 查询）

**改动：`commands.rs:1242` `session_ctx`**

在 `ShellSession`（`session.rs:27-37`）内缓存 `ShellProfile` + `AppSettings`（连接时写入，`update_shell`/`update_settings` 时失效）。`session_ctx` 优先从会话缓存取，仅授权复查（过期检查）仍需查 DB。

#### P7. 请求日志无锁化 / 降低竞争

**改动：`php.rs:173`**

将 `LazyLock<Mutex<VecDeque<RequestRecord>>>` 改为：
- 方案 A（推荐）：`parking_lot::Mutex`（几乎零成本，替换 `std::sync::Mutex`）。
- 方案 B：`crossbeam::queue::ArrayQueue<RequestRecord>` 无锁环缓冲，容量 200，满则覆盖。

#### P8. `SessionManager::get()` 清理过期

**改动：`session.rs:55`**

`get()` 改为也调用 `purge_expired()`（改为 `&mut self`），或定期后台清理任务。低优先级。

### 阶段二：安全加固

#### S1. `run_code` 命令白名单 + 限制

**改动：`php.rs:671-745` `run_code`**

- 新增可选白名单：`AppSettings.allow_arbitrary_code` 默认 `false`，开启后才能执行非插件托管的任意 PHP。
- 对 `run_code` 载荷加长度上限（如 64KB）与执行超时（复用 `default_timeout_secs`）。
- 审计记录 `run_code` 的完整载荷（脱敏后），当前仅记命令不记代码体。

#### S2. 上传签名扫描（可选）

**改动：`commands.rs` 上传/写文件入口**

写文件/上传前，对目标内容做轻量签名扫描（如 `.php` 扩展 + 常见恶意函数特征 `eval/base64_decode/assert`），命中则审计告警（不阻断，仅提示）。

#### S3. 请求日志落盘开关

**改动：`php.rs` `record_request`**

当前仅内存环缓冲（重启即失）。新增 `AppSettings.request_log_persist`，开启时追加写 SQLite（复用 `storage.rs` 审计表），便于事后追溯。

### 阶段三：功能拓展

#### E1. 新语言 stub：Python / Node

**改动：`crates/dosword-sdk/src/encoder.rs` stub 生成 + `commands.rs:generate_shell`**

参照现有 `php/asp/jsp` stub 生成逻辑，新增：
- **Python**：`import base64,subprocess` + POST 参数解码执行，nonce 帧回显。
- **Node**：`require('child_process')` 同构。

注册到 `STUB_LANGUAGES` 后，`generate_shell` 自动支持，前端下拉直接可选。

#### E2. 批量操作 API

**改动：`commands.rs` 新增 `batch_list_dir` / `batch_read` 命令**

前端文件树多选时一次往返返回多个目录/文件内容，减少 RPC 次数（配合 P1 的 stat 合并，效果显著）。

#### E3. 编码器 / 会话模式插件化增强

`EncoderRegistry`（`php.rs:52`）已支持多编码器。新增「自定义编码器」接入点：用户上传的 `.encoder` 描述文件（格式同 `dosword_sdk::encoder`），运行时注册，无需改 Rust 代码。

#### E4. UI 增强（前端）

- **终端**：分屏多 Tab、命令历史搜索（复用现有 PTY 输出流）。
- **文件管理**：拖拽上传（对接 P4 分块）、批量复制/移动（复用 `rename_path`）、大文件进度条。
- **连接管理**：断线自动重连（`connect_shell` 失败时按退避重试）。

### 2026-10-19 本轮（PHP 通道对齐 + 全编码器端到端验证）已修复

审计发现 PHP 侧是「三条通道、三套能力」，同一目标换个编码方式就少一半功能；
本轮补齐并对每个编码器加了真实往返测试。修出的**实际缺陷**（不是理论风险）：

1. **8 个 legacy 编码器全部不可用**：`business_php_stub` 与 `xor_body` 模板里各有一段
   「执行器降级」覆盖 `$_g[0]`，而该槽位属于调用方传入的第一个符号（`base64_decode` /
   `openssl_decrypt`）→ 解包时去调用 `shell_exec(密文)`，响应恒为
   `{"code":200,"rule_size":0}`，客户端报「响应中未找到协议帧」。
   （session 模板此前修过同一个坑，这两处漏了。）
2. **legacy 通道无分块能力**：legacy 的 probe 不返回 `info` 表 → `ChunkedTransfer`
   取不到 → 分块上传/下载一律被拒。现 probe 上报完整 info 表。
3. **legacy 通道数据库只支持 mysql/pgsql 列库**，且 redis 被客户端**显式拒绝**
   （「仅 NATIVE 编码器可用」）；分阶段通道只有 3 个驱动（无 mssql/oracle/redis）。
   现三条通道共用 `php_impl::PHP_DB_*`，统一 6 驱动。
4. **命令降级链只有 NATIVE 有**：session / legacy 硬用 `@shell_exec`，
   目标禁用 `shell_exec` 时命令通道直接死。现三条通道共用 `PHP_EXEC_IMPL`
   （5 函数降级链 + `cd` + cwd 回传 + 全部被禁时给出明确错误）。
5. **P1（目录列表 stat 合并）只在 legacy 模板生效**：默认 NATIVE 与 session 仍是每项
   `is_dir` + `filesize` + `filemtime` + `fileperms` 四次调用。现三条通道统一单次 `stat()`，
   顺带消除 stub 里明文的 `fileperms(`。
6. **登记 Shell 无法设置 `session:true`**：生成器有「分阶段载荷」开关且提示"需与连接端一致"，
   但登记/编辑表单没有该字段，`update_shell` 也不接受协议参数 → 生成 session stub 后
   按 UI 登记必然连不上（只有 `xor_session` 编码器能进 session 通道）。
   现表单可改编码方式/盐/session，`update_shell` 支持协议参数（含未注册 encoder id 的保存时校验）。
7. **能力协商只上报不使用**：`session_probe` 的 `capabilities` 恒为 `None`，
   客户端只用 `ChunkedTransfer` 一个标志。现 db/exec/gzip 都按能力位门禁，
   旧 stub（不上报）保持 v1 行为。
8. **前端数据库「预览」硬编码反引号 + `LIMIT`**：pgsql/mssql/oracle 上点表名必报错。
   现按驱动分派引号与分页语法（MSSQL `TOP 100` / Oracle `FETCH FIRST 100 ROWS ONLY`）。
9. **session / legacy 通道 OPSEC 与 NATIVE 不对齐**：分阶段处理器（会落到目标
   session 文件）与 legacy 逐请求代码（base64/char 等编码器下可被直接查看）里
   明文出现 `eval`/`shell_exec`/`scandir`/`file_get_contents`/`stream_socket_client`
   等敏感函数名。现改为**随代码自带**的 crc32b 运行时符号表：函数名只以哈希出现，
   运行时从 `get_defined_functions()` 反查；`eval` 用大小写混合 + 注释分隔。
   符号表内嵌于处理器/载荷，不依赖目标 stub 版本。
11. **NATIVE 落地 stub 的明文特征**：命令执行降级候选数组、`@exec(`/`@popen(`、
    `@eval($c)`、明文 `base64_*`、`@stat(`/`@touch(`/`@chdir(`、`gzdecode`/`gzencode`
    以及内部辅助函数名（`_x_mkdir` 等）都可被静态规则命中。现改为：
    - 命令降级链按**符号表索引** 0/20/21/22/23 探测，`__CMD__` 按索引分发（不再出现明文函数名）
    - 符号表新增 exec/system/passthru/popen/stream_get_contents/pclose/chdir/stat/touch/gzdecode/gzencode
    - eval 用大小写混合 + 随机注释分隔；响应 `base64_encode` 与请求 gzip 均走符号表
    - 内部辅助函数改为中性命名（apply/index/load/save/clear/relocate/ensure/state/dsn/query/rule/bulk/dispatch）
    - 回归：`native_stub_has_no_plain_sensitive_functions`（7 个 NATIVE 变体逐一断言）
      与 `real_php_exec_fallback_when_shell_exec_disabled`（禁用 shell_exec 后仍能降级执行）
    旧 stub 不受影响（重新生成才会更新）。
10. **NATIVE 的 gzip 压缩位置错误**：`gzip_payload` 在**加密之后**执行，
    密文是高频熵数据（XOR 变体因 32 字节周期性偶有收益，AES/ChaCha/Rabbit 下几乎无效），
    「gzip 传输压缩」形同虚设。现改为加密前压缩：请求
    `{"z":1,"d":"base64(gzip(内层 JSON))"}`，响应在加密前 gzip、客户端按魔数识别；
    新增能力位 `gzip_plain`，旧 stub 继续走密文层路径（向后兼容）。

**为什么资源/提示词延后**：它们承载的数据（Shell 列表、会话、审计）已由只读工具完整覆盖，
资源只是在客户端侧做「自动附加上下文」的 UX 增强，不影响 agent 的能力面；而实现需要
额外对接 rmcp 的 `list_resources`/`read_resource`/`list_prompts` 结构体，属纯增量、可随时补。

**已知限制**：

1. `tools/list` 会列出全部 23 个工具（含未启用级别），调用时再按级别拒绝并给出
   「请在设置中启用」的可执行提示——这样用户改完设置后客户端无需重连即可用。
2. 数据库连接参数以 `serde_json::Value` 接收（未给 SDK 的 `DbConnection` 引入 schemars
   依赖），schema 描述为 object，字段含义写在工具描述里。
3. 单调用超时 = `default_timeout_secs + 30s`；底层命令自身的 HTTP 超时保证不会无限挂起。
4. MCP 令牌与连接密码同样以明文存于本地 SQLite（现有取舍），keyring 仍在路线图中。
