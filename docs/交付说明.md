## 2. 关键设计取舍（评审时最该看的部分）

### 2.1 录制不落密钥

帧里只有：请求明文（脱敏）、HTTP 响应原文、`data` 长度。**没有**密码、令牌、AEAD 密钥。
代价：回放只能校验「外层 JSON → data → gunzip」这段不需要密钥的管线，明文解密兼容性由
既有单测 + 真实往返覆盖。

这是有意为之——为回放把密钥落盘，等于给攻击者准备一份现成的解密材料。

### 2.2 内存马的准入约束

`FilterDef` 需要 `javax.servlet.Filter` 实例；载荷必须内嵌已编译字节码（`ClassLoader.defineClass`）。
模块硬约束：**handle 必须能在全新实例上完成 uninstall**，做不到就不实现。当前卡在
`StandardContext` 注册/卸载需要容器级验证，故形态不进 `memshell_capabilities`。

### 2.3 依赖策略的例外

`wasmtime 49.0.3` 有两条未修复公告（RUSTSEC-2026-0378/0379），crates.io 尚无修复版本
（49.0.4 / 48.0.7 未发布稳定版）。处置：`deny.toml` 与 CI `cargo audit --ignore` 两处
带原因忽略、注释互指、写明解除条件。**这是有意识的例外，不是漏看。**

## 3. 验证矩阵（哪些只能 CI 验）

| 改动类型 | 本地可验 | CI 唯一可验 |
|---|---|---|
| Rust 逻辑 / 协议 / 编码 | clippy + fmt + SDK 单测 | app-crate 单测（本机 Windows GNU 测试二进制入口点缺失）、真实 PHP 往返 |
| 前端 | tsc / eslint / vitest / build | — |
| 桌面安装包 | ✗（无 MSVC/签名） | ✓ |
| Java 内存马 | ✗（无 Tomcat） | 编译期校验（容器 E2E 尚未做） |
| 发布流水线 | 仅 YAML 结构与 tag 守卫逻辑 | ✓ |

## 4. 已知限制

1. **PHP 与会话通道的录制**：已埋点，但会话帧形态（心跳/复用）尚未单独校验。
2. **`import_shells`**：已单事务化前的形态仍在（逐条事务、持库锁），大批量导入会阻塞其它命令。
3. **前端视图级测试**：vitest 覆盖编码器/协议参数/共享组件，视图交互仍靠手测。
4. **Java 内存马**：注册/卸载未实现；`.NET` 未开始。

## 5. 下一步（按价值排序）

1. **S4 收尾**：起 Tomcat 靶场（见 `docker-compose.tomcat.yml`），实现 `StandardContext`
   注册/卸载，用 `DOSWORD_REQUIRE_TOMCAT=1` 门控容器 E2E。
2. **`import_shells` 单事务化 + 异步化**：与已完成的 `export_shells`/`get_settings` 对齐。
3. **视图级测试**：补 Playbook / MCP 面板 / 录制工具条的交互用例。
4. **审计链式哈希**：防篡改与可验证导出（当前审计可写不可验）。
