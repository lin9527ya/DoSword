# DoSword 现代化方案（对标蚁剑 / 冰蝎 / 哥斯拉）

> 目标：把 DoSword 从「协议可用」推进到「工程上现代」——强密码学、可协商能力、
> 可配置流量形态、内存型载荷、可编排自动化，同时不放弃既有的授权与审计约束。
>
> 本文只描述**仅用于授权安全测试**的能力演进，不涉及任何免杀承诺。

## 1. 三个参考工具的核心机制

| 工具 | 核心机制 | 值得借鉴 | 不值得照搬 |
|---|---|---|---|
| **蚁剑 AntSword** | Electron/JS；「编码器 + 解码器」插件对；多语言 shell（php/asp/aspx/jsp/custom）；core 与 plugin 分层；交互式 shell 与文件管理 | **编码器可插拔**（一名用户可自定义任意变形）；**多语言统一抽象**；插件市场化的组织方式 | 字符串级混淆，密码学上等于没有加密；编码器与协议耦合过松导致能力无法协商 |
| **冰蝎 Behinder** | AES 全链路加密，密钥由密码派生；自定义请求头 / 假 404 / Cookie 载密；Java/.NET 内存马；端口转发与 SocksCap；插件 | **强加密是默认而非可选**；**载荷形态多样**（文件 / 内存）；**流量形态可调**（头、状态码、路径） | 密钥派生停在 MD5 级别、缺 nonce 语义与防重放；「隐蔽」优先于「可审计」，与授权场景冲突 |
| **哥斯拉 Godzilla** | Java 内存马（Filter/Servlet/Listener）；AES + 动态 key；自定义序列化 + 混淆；pluginFunction 插件体系；回显模式 | **能力注入而非文件落地**；**动态密钥**；**插件即函数**的轻量扩展模型 | 依赖 Java 生态与特定反序列化链；配置项隐晦、可维护性差 |

**共同结论**：这三者的「现代性」不在混淆技巧，而在四点——(1) 强加密 + 密钥派生，
(2) 能力/形态可协商，(3) 载荷可注内存，(4) 扩展有边界。DoSword 的差距集中在前两点。

## 2. DoSword 现状与差距

| 维度 | 现状 | 差距 |
|---|---|---|
| 密码学 | `native`/`native_*`：XOR、AES-256-ECB/CBC、DES、ChaCha20、Rabbit | **无 AEAD**（ECB 无完整性、CBC 无 MAC、XOR 无完整性）；密钥派生仅 `md5(password)`；无防重放；响应 IV 虽已修但仍是流密码复用语义 |
| 能力协商 | stub 上报 `ChunkedTransfer`，本次新增 `ProtoVersion`/`Capabilities`/`ShellType` | 已具备骨架；尚无「按能力降级/拒绝」的完整矩阵，也无可视化 |
| 传输形态 | 固定 `POST formData=` + `X-Debug-Key` | 参数名/头名/编码形态/填充均不可配（蚁剑、冰蝎都可配） |
| 载荷形态 | 仅落地文件型 | 无内存马（Java Filter / PHP auto_prepend / .NET HttpModule） |
| 会话层 | 单请求单响应 + 分块读写 + TTL 会话 | 无多路复用、无心跳、无断点续传；PTY 与文件 IO 未共享背压 |
| 扩展 | SDK 插件（Rust trait）+ 原生 `.plugin`（dlopen） | 原生化插件无沙箱、无签名；插件只能跑协议侧，不能跑宿主侧 |
| 自动化 | MCP 服务端（23 工具 + 3 资源 + 1 提示词） | 无 headless CLI、无 playbook、无 CI 式批量任务 |

## 3. 六条工作流

### W1 密码学：AEAD 成为默认（最高优先级）

**规范（可直接实现，客户端与 stub 必须逐字节一致）**

```
key   = HKDF-SHA256(ikm = SHA256(password), salt = "dosword/aead/v2", info = "dsw2")
      32 字节；请求/响应共用同一 key，靠 dir 字节域分离

请求帧 = base64( nonce[12] || seq[8 BIG-ENDIAN] || AES-256-GCM(key, nonce, plaintext, aad) )
         aad = "dsw2" || 0x01 || seq
响应帧 = base64( nonce[12] || seq[8 BIG-ENDIAN] || AES-256-GCM(key, nonce, plaintext, aad) )
         aad = "dsw2" || 0x02 || seq

nonce  : 每条消息随机（getrandom / random_bytes），不复用
seq    : 每方向独立单调递增；接收端维护 64 位滑动窗口拒绝重放
```

- 编码器 id：`native_aead`（PHP 用 `openssl_encrypt('aes-256-gcm', OPENSSL_RAW_DATA, ..., $tag, $aad)`；
  密钥用 `hash_hkdf('sha256', hash('sha256', $password, true), 32, 'dsw2', 'dosword/aead/v2')`）。
- Rust 侧新增依赖：`aes-gcm`（RustCrypto，纯 Rust，无 C 依赖）。
- **失败即失败**：解密/验 tag/seq 任一失败即报错，绝不「降级用明文重试」。
- 测试：NIST 向量 + 篡改检测（翻转 1 字节必须失败）+ 重放拒绝 + 乱序窗口。
- 迁移：新 stub 默认产出 `native_aead`；旧 stub 继续可用（能力协商判定版本）。

> 本次未实现的原因：PHP 侧往返只能由 CI 验证（本机无 php），在无法本地验证的情况下
> 交付「新密码学协议」风险过高；故本次先落能力协商（W5），让 AEAD 可被安全地灰度引入。

### W2 传输形态：Transport Profile

把现在写死的请求形态抽成每 Shell 的配置（存 `protocol_params.transport`，无需 DB 迁移）：

```json
{ "param": "formData", "header": "X-Debug-Key", "encoding": "form",
  "extraHeaders": {"X-Requested-With": "XMLHttpRequest"},
  "pathSuffix": "?v=1", "padding": 0 }
```

- 客户端：`native_call` 从 profile 取值构造请求（参数名、头名、额外头、查询串、随机填充）。
- 服务端：**参数名必须与 stub 一致**，故 `stub()` 需接受参数名 —— 通过 `Encoder` trait
  增加 `fn stub_with(&self, language, password, opts: &StubOptions)`，默认 `stub()` 转调、
  opts 缺省为历史值（向后兼容）。
- 验收：同一编码器可用两种参数名生成两份 stub 并各自连通；旧配置不受影响。

### W3 载荷形态：内存型

| 语言 | 形态 | 注入方式 |
|---|---|---|
| Java | `Filter` 内存马 | 反序列化链写入 `StandardContext` 的 FilterDef/Map（需容器版本适配，先支持 Tomcat 8/9） |
| PHP | `auto_prepend_file` / `.user.ini` | 写入受控目录 + `.user.ini`，或 `php_value` 于 `.htaccess`（Apache） |
| .NET | `HttpModule` | `web.config` 的 `modules` 节点 |

- 共性接口：`trait PayloadInstaller { fn install(&self, session) -> Result<Handle>; fn uninstall(&self, handle) }`
- 必须配套「卸载」与「存活检测」，否则等于给目标留后门（与本工具的授权定位冲突）。
- 验收：注入 → 请求经内存马 → 卸载 → 再请求失败；全过程写审计。

### W4 会话层：多路复用 / 心跳 / 续传

- **多路复用**：一次 HTTP 往返携带多个逻辑调用（batch），降低请求数（对 WAF 友好、更快）。
- **心跳**：会话空闲时低频探活，掉线即标记 `stale` 并在 UI 显示（当前只靠 TTL 过期）。
- **断点续传**：上传/下载维护 `(session, path, offset, hash)` 检查点，中断后从检查点续传；
  依赖已有的 `read_chunk`/`write_chunk` 偏移语义。
- **背压**：PTY 与文件流共享一个令牌桶，避免 agent 高频轮询打满目标（MCP 侧已限流，协议侧未限）。

### W5 能力协商（本次已实现）

- stub 上报：`ProtoVersion=2`、`Capabilities=chunked,stream,db,plugin,exec`、`ShellType=file`。
- 客户端：`TargetCapabilities::from_info()` 解析 → `ProbeResult.capabilities` /
  `ConnectResult.capabilities` → 生成 TS 类型 → MCP `dosword_probe_session` 直接可见。
- 兼容策略：旧 stub 无 `ProtoVersion` → `None`（按 v1 旧行为）；有列表但缺某项 → 精确拒绝。
- 后续：把 `db`/`plugin`/`stream` 的判定接入 `PhpSession`，缺能力时返回「请重新生成 stub」。

### W6 扩展与自动化

- **WASM 沙箱插件**：把宿主侧插件（非协议侧）从 `dlopen` 原生库改为 WASM（wasmtime），
  插件声明所需能力（读文件/网络/执行），未声明即拒绝——替代当前「原生库无沙箱」。
- **Playbook**：YAML 描述一串 MCP 工具调用（含前置条件与断言），可 CI 化跑授权范围内的回归。
- **CLI**：`dosword-cli` 复用同一服务层，支持 `--json` 输出，便于脚本与 agent 调度。

## 4. 分期路线

| 阶段 | 内容 | 估时 | 验收 |
|---|---|---|---|
| **P0（本次已完成）** | 能力协商 v2（stub 上报 + DTO + TS + 测试） | 0.5 天 | 新旧 stub 都能连；probe 返回 capabilities；4 个单测 |
| P1 | AEAD 编码器 `native_aead`（W1） | 2 天 | NIST 向量 + 篡改/重放测试 + CI 的 PHP 往返 |
| P2 | Transport Profile（W2）+ 心跳（W4 子集） | 2 天 | 双参数名 stub 各自连通；掉线可见 |
| P3 | 内存型载荷（W3，Java 优先）+ 卸载 | 3 天 | 注入/卸载闭环 + 审计 |
| P4 | WASM 插件沙箱（W6）+ Playbook | 4 天 | 越权插件被拒；playbook 可跑 |

排序理由：密码学先于形态（W1 是「对不对」的问题，W2/W3 是「像不像」的问题）；
能力协商先行，才能让 W1 灰度而不破坏存量。

## 5. 本次实际交付（尽量具体）

1. `TargetCapabilities`（SDK DTO）：`protoVersion` / `capabilities[]` / `shellType`，
   含 `from_info` 解析（大小写归一、空项过滤、`ChunkedTransfer` 折算）与 4 个单测。
2. `ProbeResult.capabilities`、`ConnectResult.capabilities`（连接与探测都带能力）。
3. PHP stub：`__ENV__` 与分阶段处理器 `probe` 均上报
   `ProtoVersion=2` / `Capabilities=chunked,stream,db,plugin,exec` / `ShellType=file`。
4. ts-rs 重新生成 → 前端与 MCP 工具输出自动带上能力信息。
5. 兼容性：旧 stub（无 ProtoVersion）→ `capabilities = null`，行为与之前完全一致。

**未实现（明确登记）**：W1 AEAD、W2 Transport Profile、W3 内存马、W4 多路复用/续传、
W6 WASM 沙箱与 CLI。原因见各节与 P1 备注（需要 PHP/容器侧验证，且不应在无法本地验证时
交付新密码学协议）。

## 6. 风险与合规边界

- 新密码学的**错误实现比不加密码更危险**：AEAD 必须配向量测试与篡改测试，且 CI 必须跑
  PHP 往返；本地无 php 时不得宣称「已验证」。
- 内存型载荷会**改变目标进程状态**，必须提供卸载与存活检测；无卸载能力的形态不予实现。
- 传输形态可配 ≠ 免杀承诺：本项目不提供、也不承诺绕过任何具体安全产品。
- 所有新增能力都必须过既有的三层门禁（真实网络开关 / Workspace 授权范围 / 审计），
  不得出现绕过路径；MCP 侧继续遵守 read/write/exec 分级与执行级人工确认。
